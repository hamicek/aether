Supervision and messaging for real processes, across languages.

aether is a polyglot, OTP-inspired runtime over NATS. A lord starts your programs as isolated OS processes, watches them, restarts them when they crash, and lets them talk over a message bus. One crash does not sink the rest. No Erlang, no sidecar, no Kubernetes.

The model

If you know OTP, you already know aether.

A supervisor and its genservers, here over NATS and across languages. The names carry the flavor; the model is plain supervision and message passing.

lord = Supervisor

Spawns thralls as OS processes, watches them, restarts them per a strategy you choose, drains them on shutdown.

thrall = GenServer

State plus a serialized mailbox, so no locks. Also comes as an FSM (gen_statem) and an event manager (gen_event).

ether = message transport

Embedded NATS or an external cluster. Sync call, fire-and-forget cast, optional durable delivery.

What it's for

Tens of long-running processes that must stay alive and talk.

Not millions of tiny in-VM actors (reach for BEAM there). aether earns its keep once you have several processes that must be supervised, isolated, and reliably connected.

01 · edge / IoT / SCADAPROVEN

A site that ingests telemetry and watches alarms

Protocol drivers feed a coarse-grained site process on a serialized mailbox; threshold alarms push live to a browser over SSE. The runtime is proven by the spike; the domain sits on top.

50,000 values/s · alarm p99 < 1 ms
02 · polyglot services

A gateway and workers in different languages

One lord plus thralls in Go, TS and Python side by side, over call and cast. Want a pool? replicas = N load-balances through a NATS queue group for free.

03 · hub and spoke fleet

Sites that must not see each other

Each site is a leaf node bound to its own account: a hard, structural boundary, not careful code. The hub still assembles a fleet-wide health view. Partition-tolerant by design.

04 · durable pipeline

A task stream that survives a restart

Durable thralls (casts survive a crash via JetStream) plus a worker pool plus an event log: state is rebuilt by replaying the log, not from a snapshot. The log is truth.

Quickstart

A thrall is a handful of handlers. The rest is a manifest.

Write the same tiny genserver in any of the three languages. Durability, replicas and supervision policy are manifest concerns, not code.

counter.ts
import { defThrall, start } from "@hamicek/aether";

const counter = defThrall<number>({
  name: process.env.AETHER_NAME ?? "counter",
  init: () => 0,
  handleCall: { get: (_p, s) => [s, s] },  // [reply, newState]
  handleCast: { inc: (_p, s) => s + 1, dec: (_p, s) => s - 1 },
  terminate: (reason, s) => console.log(`exiting ${reason}, last=${s}`),
});

await start(counter);
bring it up
# start the ether + the lord from a manifest
$ aether up -f aether.toml

# status of every thrall, from the registry
$ aether ps

# the live lifecycle stream
$ aether events

# poke a thrall by hand
$ aether cast counter inc
$ aether call counter get
=> 3

The same thrall exists in counter_py.py and counter_go.go, functionally identical. Turn on durability with durable = true in the manifest. Let a handler crash cleanly with escalate("...") and the lord restarts it through init.

Implemented and exercised for real
Supervision
one_for_one, one_for_all, rest_for_one, plus a restart-intensity window and backoff.
Graceful drain
A thrall finishes its mailbox, runs terminate, then escalates to SIGTERM/SIGKILL.
Liveness fencing
No thrall outlives its lord: a KV lease self-terminates orphans, even on external SIGKILL.
Durable mailbox
casts survive a crash via JetStream, in all three SDKs.
Event-sourced rebuild
State survives a restart by replaying an append log, not a snapshot.
HTTP / SSE edge
Map a route to a thrall op with no code; push live to the browser, scoped per client.
Secured bus
Server TLS, mandatory nkeys, three least-privilege roles, rotation without downtime.
Fleet health
Each lord publishes a curated summary; aether fleet aggregates across the bus and leaf sites.
Observability
Structured logs, a Prometheus endpoint, heartbeat miss detection, cross-process tracing.
